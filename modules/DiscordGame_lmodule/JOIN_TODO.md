# Discord "Приєднатися" (Ask to Join) — план на майбутнє

Статус: **не реалізовано, не почато**. Цей файл — нотатки з дослідження, щоб не
передивлятись усе заново, коли вирішимо братись за фічу.

## Як це працює технічно (перевірено по джерелах discord/discord-rpc)

- Реєстрація автозапуску — запис у Windows Registry:
  `HKEY_CURRENT_USER\Software\Classes\discord-<appId>`
  - `(Default)` = `"URL:Run game <appId> protocol"`
  - `URL Protocol` = `""` (маркер, порожній рядок)
  - `DefaultIcon\(Default)` = шлях до exe (тільки для іконки)
  - `shell\open\command\(Default)` = шлях до exe **БЕЗ** `%1` чи будь-якого плейсхолдера
    — команда фіксована, без динамічних аргументів для конкретного запрошення.
- **Секрет приєднання НЕ передається через аргументи командного рядка.** Discord
  доставляє його виключно через живий IPC-зв'язок, коли застосунок (новозапущений
  чи вже запущений) підключається з тим самим `appId` і викликає `onActivityJoin(secret)`.
- Бібліотека `discord-game-sdk4j` (яку ми використовуємо, v1.0.0) **не реалізує
  `registerCommand`** (сама лише "створює ярлик", за їхнім же коментарем) — запис
  у реєстр треба робити самим, бібліотека тут не допоможе.

## Обсяг роботи — 3 проєкти

1. **DiscordGame_lmodule (Java)**
   - Зареєструвати `DiscordEventAdapter`/`onActivityJoin(String secret)` через
     `CreateParams.registerEventHandler(...)` (зараз не зареєстровано взагалі).
   - Виставляти `activity.party()` (id, розмір) і `activity.secrets().setJoinSecret(...)`
     коли гравець на сторінці конкретного сервера (зараз party/secrets ніде не викликаються).
   - Секрет має однозначно кодувати сервер/профіль (наприклад, UUID профілю).
   - Коли прийшов `onActivityJoin(secret)` — потрібен зворотний міст **модуль → рантайм**
     (протилежний напрямок від того, що вже є для статусів; той самий підхід через
     reflection, але тепер рантайм має надати метод "обрати сервер X і натиснути play").

2. **LauncherPrestarter (C#, Windows-only)** — потрібен лише для сценарію
   "у друга лаунчер взагалі не запущений":
   - Одноразовий запис реєстру (`Microsoft.Win32.Registry`) при старті —
     `HKEY_CURRENT_USER\Software\Classes\discord-<appId>\shell\open\command` → шлях
     до `LauncherPrestarter.exe`.
   - Без цього кроку "Приєднатися" все одно працюватиме, але тільки якщо в друга
     лаунчер вже відкритий (Discord не зможе його запустити сам).

3. **LauncherRuntime-4.0.6 (JavaFX)**
   - Метод "обрати профіль за UUID/hash і перейти в ServerInfoScene" (або одразу
     запустити клієнт) — викликається модулем через reflection-міст, симетрично
     до `DiscordPresenceBridge`, який уже є (рантайм → модуль).

## Обмеження

- Повний автозапуск (реєстр) — **тільки Windows**. Linux/macOS: join працює
  лише між уже запущеними копіями лаунчера (секрет + party — платформо-незалежні,
  реєстрового автозапуску там нема).
- "Ask to Join" кнопка в Discord з'являється лише коли одночасно задані
  `party` (з вільним місцем, currentSize < maxSize) І `secrets().joinSecret`.

## Два варіанти старту (ще не обрано)

- **A. Тільки join між запущеними** — не чіпаємо Prestarter, лише пункт 1 і 3
  (party+secret+onActivityJoin+міст вибору сервера). Кнопка працює, якщо у
  друга вже відкритий лаунчер.
- **B. Повний з автозапуском** — додатково пункт 2 (реєстр у Prestarter),
  Windows-only частина.

Рекомендація (не остаточне рішення): почати з A, і за потреби додати B пізніше —
вони не конфліктують, B суто надбудова над A.
